05 / FTTH NETWORK INTELLIGENCE

Trace the physical network, layer by layer.

Explicit FTTH asset hierarchy for planning, installation, maintenance and monitoring. The hierarchy below is a domain model, not a claim of live inventory or a connected OLT/NMS.

MODEL / LIVE STATE UNVERIFIED
G-PON / OLT→Main cabinet→Passive cabinet
LAYER 01

G-PON / OLT

OLT identity, chassis/card/PON port, upstream feeder, capacity and trusted telemetry provenance.

Live NMS/OLT readings require a configured provider adapter.
LAYER 02

Main cabinet

Cabinet fed from the OLT/feeder side, with explicit incoming cable/core and outgoing passive-cabinet links.

Capacity and port occupancy must come from authorized records.
LAYER 03

Passive cabinet

Passive distribution, splitter stages and port-to-port continuity, with upstream/downstream relationships.

Splitter ratios and losses are engineering inputs, not measured truth.
Passive cabinet→Main box→Riser cable / floor box→Customer fiber / ONT
LAYER 04

Main distribution box

Street/building distribution point mapping each incoming cable/core to downstream boxes and customer drops.

LAYER 05

Riser cable and floor boxes

Building → floor → riser → riser-box hierarchy. Each floor box and riser segment has its own identity and traceable upstream link.

LAYER 06 / EVIDENCE REQUIRED

Customer fiber / ONT

Drop cable, termination, customer/service association and ONT identity. Acceptance requires trusted field evidence and optical measurements.

Asset identity and lineage

Unique asset ID, parent/child link, cable/core continuity, location provenance, lifecycle state and change history.

Installation and acceptance

Survey → design → material → civil/duct → cable → splice → test → QC → acceptance → activation. Each promotion requires its own recorded evidence.

Faults and monitoring

Trace affected services downstream, correlate alarms only when a real adapter is connected, and separate calculated optical budget from measured OTDR/power-meter evidence.

TRUTH BOUNDARYNo live asset count, port availability, optical level, technician location or NMS alarm is created by this page. Those values must arrive through authorized APIs with source and freshness metadata.
