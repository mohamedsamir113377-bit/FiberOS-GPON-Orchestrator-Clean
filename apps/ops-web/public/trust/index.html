Security and source-access boundaries

  • Source repository: the GitHub product repository is private. A public preview does not grant repository access or deliver the source distribution.
  • Browser code: HTML, CSS, JavaScript, and other assets sent to a browser can be inspected or copied. No honest seller can guarantee that a public website's client-side assets are impossible to copy. The preview is not the source-code license or delivery package.
  • Secrets and data: database credentials, signing keys, and privileged server logic must remain server-side and must never be embedded in public client assets. Buyer credentials and production data should not be entered into this preview.
  • Browser protections: the deployment configuration defines Content Security Policy, HSTS, anti-framing, MIME-sniffing, referrer, and cross-origin headers. These controls reduce browser-side attack surface; they do not prove that every backend or external integration is secure.
  • Database and runtime: production network restrictions, least-privilege grants, populated-tenant isolation, backup/recovery, and buyer-owned live acceptance must be verified for the exact release and deployment. Source tests alone are not a production security certification.
