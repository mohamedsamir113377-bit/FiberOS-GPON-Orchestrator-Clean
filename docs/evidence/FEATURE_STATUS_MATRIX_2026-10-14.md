## 3. Required hold on migration 188

The source file `sql/migrations/188_enterprise_time_machine.sql` declares a **per-tenant** hash chain in `ecl_chain()`, but `ecl_verify_chain()` uses one global `prev` while iterating all tenants by `seq`. With multiple tenants, that verifier does not validate each tenant's independent chain correctly. The writer's hash input also omits the `actor` field, so the hash does not bind that field. The migration comments show how to attach `ecl_capture`, but the migration does not attach capture triggers to the actual operational tables. It explicitly labels `app.tenant_id` as an assumption to verify against the application's real RLS convention.

**Decision:** do not apply migration 188 to production until the per-tenant verifier, canonical hash payload (including actor and unambiguous field encoding), actual table triggers, and tenant-setting compatibility have been corrected and adversarially tested on a clean Neon test branch. The test branch's four routines/table are not enough for production acceptance.
